# Explore With Me

Explore With Me — микросервисное приложение для публикации событий, поиска мероприятий, формирования подборок и подачи заявок на участие.

Проект построен на Spring Boot и Spring Cloud. Функциональность разделена между независимыми сервисами, которые взаимодействуют друг с другом через REST API и OpenFeign.

## Архитектура

Проект состоит из инфраструктурных, бизнес- и статистических сервисов.

Обнаружение сервисов выполняется через Eureka Server.

Централизованная конфигурация сервисов предоставляется Config Server.

Внешние HTTP-запросы проходят через API Gateway.

Межсервисное взаимодействие выполняется с помощью OpenFeign.

## Основные сервисы

### User Service

Сервис управления пользователями.

Отвечает за:

- создание пользователей;
- получение информации о пользователях;
- удаление пользователей;
- предоставление данных пользователей другим микросервисам.

Использует собственную базу данных `ewm-user`.

### Event Service

Сервис управления событиями.

Отвечает за:

- создание и редактирование событий;
- публикацию и отклонение событий;
- категории;
- локации;
- публичный и административный поиск событий;
- хранение количества подтверждённых заявок.

Для получения информации об инициаторах событий взаимодействует с `user-service` через OpenFeign.

Использует собственную базу данных `ewm-event`.

### Request Service

Сервис управления заявками на участие в событиях.

Отвечает за:

- создание заявок;
- отмену заявок;
- подтверждение и отклонение заявок;
- контроль лимита участников.

Для проверки пользователей и получения информации о событиях взаимодействует с `user-service` и `event-service` через OpenFeign.

Использует собственную базу данных `ewm-request`.

### Compilation Service

Сервис управления подборками событий.

Отвечает за:

- создание подборок;
- изменение подборок;
- удаление подборок;
- получение публичных подборок.

В базе данных хранит идентификаторы событий.

Информацию о самих событиях получает из `event-service` через OpenFeign.

Использует собственную базу данных `ewm-compilation`.

### Stats Server

Сервис статистики просмотров.

Отвечает за:

- сохранение информации об обращениях к эндпоинтам;
- получение статистики просмотров;
- подсчёт уникальных просмотров.

Использует собственную базу данных `ewm-stats`.

## Инфраструктура

### Eureka Server

Используется для регистрации и обнаружения микросервисов.

```text
http://localhost:8761
```

### Config Server

Предоставляет централизованную конфигурацию микросервисов.

Конфигурационные файлы расположены в:

```text
infra/config-repo
```

### API Gateway

Является единой точкой входа во внешнее API приложения.

```text
http://localhost:8080
```

Gateway маршрутизирует запросы к соответствующим микросервисам через Eureka.

## Хранение данных

Каждый бизнес-сервис владеет собственной базой данных.

| Сервис | База данных | Порт хоста |
|---|---|---:|
| Stats Server | `ewm-stats` | 6542 |
| User Service | `ewm-user` | 6543 |
| Request Service | `ewm-request` | 6544 |
| Event Service | `ewm-event` | 6545 |
| Compilation Service | `ewm-compilation` | 6546 |

Между базами данных разных микросервисов отсутствуют внешние ключи.

Связи между сущностями разных сервисов представлены идентификаторами, а необходимые данные запрашиваются через API соответствующего сервиса.

## Межсервисное взаимодействие

Для взаимодействия между микросервисами используется OpenFeign.

Основные зависимости:

```text
event-service
    └── user-service

request-service
    ├── user-service
    └── event-service

compilation-service
    └── event-service

event-service
    └── stats-server

compilation-service
    └── stats-server
```

Для получения коллекций связанных сущностей используются пакетные запросы, чтобы избежать проблемы N+1.

Например, `event-service` получает несколько пользователей одним запросом, а `compilation-service` получает несколько событий через пакетный метод `EventClient`.

Используются отдельные PostgreSQL-контейнеры:

```text

request-db
event-db
compilation-db
```

Для бизнес-сервисов подготовлены отдельные Dockerfile:

```text

core/request-module/Dockerfile
core/event-module/Dockerfile
core/compilation-module/Dockerfile
```
